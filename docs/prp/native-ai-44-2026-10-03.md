## Server contract (3.2.1)

### Feature detection

- **Flag:** `GET /api/ui_settings/` returns the flag at **`settings.ai_enabled`** (`views.py:4272`).
  - The key is absent on 2.x. Treat a missing key as `false`.
  - The value is `app_config.ai_enabled` when it is set, otherwise the env var `PAPERLESS_AI_ENABLED` (default NO).
  - The flag does **not** mean a backend is configured.
- **Same response:** it also carries `permissions`. Use that to hide AI suggestions for users without `change_document`.
- **What makes chat work:** chat also needs an embedding backend plus a built vector index.
  - Only admins can see whether these exist, through `/api/status/` (`tasks.llmindex_status`, which returns 403 for normal users).
  - `OK` doesn't prove an index exists, because the nightly `llm_index` task reports SUCCESS as a no-op when AI is off.
  - In practice, a client learns chat isn't ready only from the in-band "couldn't find any content" sentence.
- **API version:** no AI endpoint or field depends on it. v9 and v10 behaved identically.

### `POST /api/documents/chat/`

**Request**
- Route: `paperless/urls.py:202-204`. View: `ChatStreamingView` (`documents/views.py:2410-2456`).
- JSON body:
  - `q`: required, non-blank, **at most 4000 characters**.
  - `document_id`: optional nullable int. A value of `0` is treated as absent.
- Permission: authenticated plus the global `documents.view_document`.
- **Single-turn only.** There are no history fields. Prompt: "Using only the context above, answer the query".
- Retrieval:
  - **Without `document_id`:** it searches documents the user is allowed to see (`permitted_document_ids`). Superusers only have trashed documents excluded.
  - **With `document_id`:** it searches only that document.
  - It takes the top 5 chunks and returns at most 3 references.

**Response**
- Status 200 with `Content-Type: text/event-stream`, but the body is **not SSE**: no `data:` lines, no event names.
- The body is raw text deltas, then an optional trailer:
  ```
  <answer text…>\n\n__PAPERLESS_CHAT_METADATA__{"references":[{"id":6,"title":"…"}]}
  ```
- The trailer is only present on success when references exist. Titles come from index time, so they can be stale.
- The stream ends when the connection closes.

**In-band errors**
- These arrive after a 200, appended to any partial text, with no trailer. Both are **English-only**:
  - `Sorry, something went wrong while generating a response.`
  - `Sorry, I couldn't find any content to answer your question.`
- The second one covers both "no index" and "nothing relevant".

**Error statuses**

| Status | Content type | Meaning |
|---|---|---|
| 400 `AI is required for this feature` | `text/html` | AI is disabled. This check runs first. |
| 400 | DRF JSON | Bad request body |
| 400 `Document not found` | text | The document doesn't exist or is trashed |
| 403 `Insufficient permissions` | text | No permission |

**Delivery**
- On this deployment (granian ASGI, sync generator, Django 5.2) Django runs `sync_to_async(list)` over the generator. The headers probably arrive first, and then the **whole body arrives in one burst** at the end.
- Don't rely on progressive rendering.
- Not verified live.

**Compression**
- 3.2.0 skips gzip for `text/event-stream`.
- Older 3.x servers may gzip-buffer the stream, so send `Accept-Encoding: identity`.

**Accept header**
- `Accept: text/event-stream` on its own returns **406**, so send `Accept: application/json; version=9` as usual.
- The 406 was tested on `ui_settings` and is inferred for chat.

### `GET /api/documents/{id}/ai_suggestions/`

**Location and permission**
- `DocumentViewSet.ai_suggestions` (`views.py:1598-1619`, response at 1749-1779, schema at 905-935).
- Requires **`change_document`** on that document.

**Response** (example built from the source):
```json
{"title":"…",
 "tags":[3,7],          "suggested_tags":["Utilities"],
 "correspondents":[12], "suggested_correspondents":[],
 "document_types":[2],  "suggested_document_types":[],
 "storage_paths":[],    "suggested_storage_paths":["Bills/2024"],
 "dates":["2024-03-31"]}
```
- The plural keys are **IDs of objects that already exist**. They are permission-filtered and matched by fuzzy name match at 0.8.
- `suggested_*` keys are names with no match. The endpoint **never creates objects**.
- Correspondent, type and storage path arrive as lists. Take `[0]`.
- Caps: 10 tags, 4 each for the other three, 3 dates, a 128-character title.
- `dates` are raw strings from the AI model and are not validated.

**Caching and limits**
- The server caches the result per document, model and user for 50 minutes, sliding.
- The cache is invalidated on any save of the document.
- There is **no rate limit**.

**Latency**
- One call to the AI model. Two when an output language is set, which defaults to the user's UI language.
- Each call can take up to 120 s.
- **The server sends no bytes until it has finished.** A request slower than Cloudflare's roughly 100 s limit therefore gets a **524**.

**Error statuses**

| Status | Content type | Meaning |
|---|---|---|
| 404 | | No such document |
| 403 | text | No permission |
| 400 `AI is required…` | text | AI is disabled |
| 400 `{"ai":["Invalid AI configuration."]}` | JSON | The server's AI settings are wrong |
| 503 `{"ai":["AI backend request timed out."]}` | JSON | The AI backend timed out |
| 502 `{"ai":["AI backend rejected the request…"]}` | JSON | The AI backend returned an error |
| **500 HTML** | `text/html` | The AI backend can't be reached. These errors aren't mapped by the server. |

**Embeddings**
- Suggestions don't need embeddings. Without them the server falls back to Tantivy "more like this".

### Other 3.x changes

- **Workflows:** there's a new workflow action type **8 `apply_ai_suggestions`** (3.1.0 and later). The app's workflow model must tolerate unknown action types.
- **Admin surfaces (`/api/config/`, `POST /api/tasks/run/`):** out of mobile scope.
- **Version history:**
  - The module first shipped in 3.0.0-rc1, and the endpoints are absent on 2.20.15.
  - The chat format has been the same since rc1.
  - Suggestions changed from `view_document` to `change_document` in 3.0.0.
  - 3.2.0 added the 502 mapping, the per-user suggestions cache and the compression fix.

## Current app (what this touches)

**Current AI chat**
- It is **Paperless-AI only**.
- It uses its own Dio (`chat_notifier.dart:12-32`, `chat_service.dart`) with JWT/cookie login, and no Paperless-ngx token or CSRF.
- Settings live in global secure-storage keys (`ai_chat_url/username/password`). Nothing clears them on logout or profile switch.

**Existing stream parser** (`chat_service.dart:244-348`)
- It is tied to Paperless-AI's `data: {"content"}` + `[DONE]` format.
- It **decodes UTF-8 one chunk at a time** (`:294`). A multi-byte character split across chunks throws `FormatException`. **This is a bug today, separate from #44.**
- No `CancelToken`, no stop button.

**Gating**
- The rule is "Paperless-AI URL set".
- It is checked at: `document_detail_screen.dart:164`, `chat_screen.dart:44-45` and `:140`, and `settings_screen.dart:196-233`.
- The Chat nav tab (`app.dart:492-498`) is **always shown**.

**Server capabilities**
- The app has **no server-capability detection** (`ui_settings`, `remote_version`).

**Main Dio** (`dio_client.dart`)
- Token and CSRF interceptors are already in place.
- `receiveTimeout` is 30 s. In Dio this is also the allowed gap between chunks.
- `_RetryInterceptor` **retries GETs on timeout up to 3 times**.

**Existing suggestion features are local, not AI**
- `MetadataMatcher` runs on-device: OCR text at upload, and `doc.content` in the Inbox.
- The Inbox accept is a PATCH, and it does not write the AI edit trail.

**`AiEdits` trail** (Drift)
- It exists, but only the upload screen writes to it (`source: 'ocr_suggestion'`).
- It stores raw IDs, not names.

**Tests**
- No tests cover chat, the stream parser, `MetadataMatcher` or the Inbox suggestions.
- The `http_mock_adapter` and fake-adapter test setups both exist already.

## Plan

**Order: suggestions before chat.**
- Suggestions are one request and one response, need no embeddings, and can be fully tested with fixtures.
- An `ai_enabled: true` flag says almost nothing about whether chat works.

**Phase 0: detect the feature.**
- `GET api/ui_settings/`, reading `settings.ai_enabled` (missing means false) and `permissions`.
- Cache it in the `api_providers.dart` keepAlive style, per server profile.
- Clear it on logout and on profile switch.
- Fixture tests: a 2.x response, 3.x with the flag off, 3.x with the flag on.

**Phase 1: AI suggestions on document detail.**
- Add a "Suggest with AI" action. Show it only when `ai_enabled` is true and the user has `change_document`.
- **Call it only on an explicit tap**, never automatically. Every call costs the user, and the server has no rate limit.
- **Exempt this request from `_RetryInterceptor`**. Otherwise one tap could become 4 calls to the AI model.
- Give it its own `receiveTimeout` of about 150 s.
- Map every error status to a message: 400 plain text, 400/502/503 JSON, 403, 404, 500 HTML, and 524. Check `Content-Type` before decoding.
- Show the existing-object IDs as suggestion chips, reusing the stamp-chip pattern.
- Show `suggested_*` names as information only. Creating new objects is out of scope for v1.
- Parse `dates` defensively.
- Accept through `DocumentDetail.updateField`, which is a single batched PATCH.
- Write `AiEdits` rows with source `native_ai`.
- Tests: suggestion mapping, each error path, and retry exemption.

**Phase 0: DONE (`fa9508e`).** `effectiveServerCapabilitiesProvider` is the only consumer API. Users without `view_uisettings` get a 403 from `ui_settings`, which also fails closed.

**Phase 1: facts from the live AI test server (2026-10-04).** Paperless-ngx 3.2.1 on this workstation, running `gemini-3.5-flash-lite` through OmniRoute. Fixtures are in the session scratchpad until they are copied into `test/fixtures/api/`.

**Document permission flag**
- `user_can_change` (bool) is on every item of `/api/documents/` and on the default detail response. It is **absent with `?full_perms=true`**, which sends `permissions` instead.
- Values seen:
  - admin: true
  - view-only user: false
  - user with global `change_document` but only object-level view on the document: false, and the suggestions call returns 403 with no model call.
- **So the button gates on `doc.userCanChange == true`**, not on the global permission.

**Responses**

| Status | Body | Notes |
|---|---|---|
| 200 | see the bill example below | 6.8 s for the bill, 1.4 s for the tax letter |
| 403 | `text/html` `Insufficient permissions` | |
| 404 | JSON `{"detail":…}` | |
| 502 | JSON `{"ai":["AI backend rejected the request. Check logs for details."]}` | captured for real |

Bill example (200):
```json
{"title":"Electricity Bill - March 2026","tags":[2],"suggested_tags":["Electricity","Energy"],"correspondents":[1],"suggested_correspondents":[],"document_types":[1],"suggested_document_types":["Electricity Bill","Invoice"],"storage_paths":[],"suggested_storage_paths":["Utilities/Electricity","Finance/Bills"],"dates":["2026-03-31","2026-04-15"]}
```
- The model proposes **new** names even when an existing object matched; here a `Bill` type already exists.
- `dates` mixes different kinds of date. On the bill they were a statement date and a due date.

**Server-side gotcha (not ours)**
- Paperless forces a tool call. `openrouter/anthropic/claude-sonnet-5.5` through Bedrock rejects that with `tool_choice … not supported for this model`, and the user gets a 502.
- Gemini and GPT routes work.
- OmniRoute's `auto/claude-sonnet` served `inclusionai/ling-3.1-flash`, which isn't Sonnet.

**Phase 1: UX decisions**
- **Entry point:** "Suggest with AI" in the document-detail actions sheet. Show it only when `effectiveServerCapabilities.aiEnabled && doc.userCanChange == true`.
- **Retry:** when the detail screen opens and the base `serverCapabilitiesProvider` is in an error state, refresh it once. Refresh only on error, so the button doesn't flicker.
- **The request:** an explicit tap, cancellable, a 150 s `receiveTimeout`, and **no retry**. That last part needs an opt-out in `_RetryInterceptor`, set through request `extra`.
- **Result: open the existing `MetadataSheet` pre-filled.**
  - **Correspondent and type:** the first suggested existing ID, marked as suggested. If there is no suggestion, keep the current value.
  - **Tags:** current tags plus the suggested existing IDs. Suggestions only add tags, never remove them.
- **`topSlot` shows:**
  - The suggested title with a "Use this title" checkbox, off by default.
  - The AI dates, as **info only**: `created` is never pre-filled, because the dates can be due dates.
  - "Not in your library": the `suggested_*` names. Creating them is out of scope for v1.
  - Suggested storage paths, as info only. The sheet has no storage-path field.
- **Pre-fill only what's empty**, the same rule the Inbox uses.
  - Correspondent and type are pre-filled only when they are currently **unset**. If the document already has a different value, keep it and put "AI suggests: X" in the info line.
  - Tags are additive.
  - Only pre-fill IDs that **resolve in the app's local maps** (`tagsProvider` and the others). Any that don't go to the "not in your library" line, so a stale cache can never PATCH an unknown ID.
- **No usable suggestions:** if nothing is left after filtering (no new values, no title change), show "No suggestions" instead of opening an unchanged sheet.
- **Save:** use the existing `_saveMetadata` path. Add `title` to the patch **before** its `if (patch.isEmpty) return;`, so a change to the title alone still saves.
- **No `AiEdits` rows in v1.** That section is titled "AI Applied at Upload" and shows raw IDs, so native-AI rows would be mislabelled. Make the section aware of where an edit came from, and resolve names, before writing any.
- **Retry:** the one-time capability refresh goes in `initState` (post-frame) or a `ref.listen`, guarded to run once per screen, and **never in `build()`**.
- **Errors:** show a friendly message per status, checking the content type before decoding: 400 AI disabled (text), 400 invalid config (JSON), 403, 404, 500 HTML, 502, 503, 524, and the client's own timeout.
- **Model change:** add `user_can_change` to `Document`, which needs codegen through the 3.41.3 recipe. Check whether any document fetch uses `full_perms=true`, because that response omits the field.

**Phase 2: native chat.**
- Add a new service on the **main Dio**: `ResponseType.stream`, per-call `receiveTimeout` of 300 s, the normal `Accept` header, and `Accept-Encoding: identity`.
- Decode UTF-8 incrementally (`utf8.decoder` on the stream).
- Keep the full text. Split it at `\n\n__PAPERLESS_CHAT_METADATA__`, and hide any partial delimiter while the text is arriving.
- Parse `references`.
- Treat a body that ends in one of the two sentences as a soft error.
- Add a `CancelToken` and a stop button.
- Cap the input at 4000 characters on the client.
- Make the UI clearly single-turn: each question stands on its own.
- Write a pure stream-parser unit with tests: split delimiters, split multi-byte characters, sentinels, no trailer.

**Phase 3: backend choice and gating.**
- Add a setting for the AI chat backend: Native (Paperless-ngx 3.x) or Paperless-AI. Default to Native when `ai_enabled` is true.
- Update the four gating sites, and gate the nav tab.
- Rewrite the Settings copy that only mentions Paperless-AI.

**Not in v1:**
- Inbox and post-upload AI suggestions. Only add them later as an explicit per-document action.
- Creating `suggested_*` objects.
- Multi-turn chat.

**Separate small fix, now:**
- Change the existing Paperless-AI parser to decode UTF-8 incrementally (`chat_service.dart:294`).
- It is its own commit, with a test that splits a multi-byte character across chunks.

## Risks and coordination

- **Translation work (#45):** the outside contributor's batches will touch `chat_screen.dart` and `settings_screen.dart`, which are the same files Phases 2 and 3 rewrite. Phases 0 and 1 are mostly new files. Plan the chat-screen work so it doesn't collide with the translation batches.
- **Testing with AI turned on:**
  - Nothing here has been checked against a server with AI turned on.
  - **Don't enable AI on the reviewer demo.** It's a Play review asset, and enabling AI sends its documents to an AI model.
  - Use a throwaway 3.2.1 container instead, with AI pointed at the user's LiteLLM or at a mock OpenAI-compatible server.
  - Capture real responses for fixtures there. Confirm whether the chat reply arrives all at once or in pieces, the 500 when the AI backend is unreachable, and the chat 400 bodies.
- **Cloudflare tunnels:** suggestions can hit the 524 timeout.
- **Privacy and cost:** the user's documents go to whichever AI backend their server is configured with. Only ever send them on an explicit action.
